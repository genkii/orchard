# V1

## New Structure

instead of having the current architecture:

orchard/
  nbt/
  data/
  generated/
  
which is bad design because you can only have one pack and the bundled will be normally in data/ nbt/ menaing its not optimal for people that want to develop configs.

we will redesign it to have:

orchard/
  configs/
    my-pack/
  orchard.yaml
  bundled/
    nbt/
    data/


so now we support multiple configs at once using the pack format we use now making us able to create packs under configs/ in your minecraft orchard config folder

the structure of a pack is the following

my-pack/
  data/
    test.yaml
  nbt/
    test.json
  pack.yaml

if there is no pack under configs/ the mod will use the bundled if available if not it will use vanilla worldgen like currently when no data/ nbt/ is avilable
the new structure allows for way stronger architecture and easier creating of packs for orchard. bundled will from this point up be shipped with every .jar file and the sufix -BUNDLED will be removed but there will be an -TINY sufix variant that does not ship bundled/ with it so the new architecture must be designed to only check if bundled/ exist and if no other configs exist it will use bundled/ as fall back and defaults. id they are multiple packs in configs/ it will use the first pack in the folder when iterating over them if while loading the mod says the pack is not valid print an error to logs in minecraft and continue to use the next one and so one if no config is valid fall back to bundled and if there is no bundled fall back to vanilla worldgen just like currently when no data/ and nbt/ folder with configs and files is there. If you want a speciofic pack in configs/ to be loaded orchard.yaml will contain an option like pack to set your pack


a pack.yaml will have certain definitions like:

```yaml
name: my-pack
format: 0.1
version: 1.0.0
description: My custom Orchard trees
```

the orchard.yaml is the configuration file for orchard with multiple options

```yaml
pack:
  selected: my-pack # will use orchard/configs/my-pack as default pack. the stantard value in the config will be auto which will select a pack automatically (just use first pack when iterating over packs) if the specified pack is not valid the mod will fall back to auto
```


the new files in the packs as example my-pack/data/*
are also yaml in the new version and should use yaml syntax instead of .json files because its easier to write then normal json syntax.
